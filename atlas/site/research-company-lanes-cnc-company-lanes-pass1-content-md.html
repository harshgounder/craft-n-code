1. Scope, Evidence Standard, and What the Search Did Not Prove

1.1 Three labels that prevent overconfidence

This report uses three labels. VERIFIED means that the retrieved source excerpt directly states the fact. INFERRED means a reasoned prediction from a verified pattern, the team's supplied context, or a product direction; it is not evidence that the event organizer will use that pattern. UNVERIFIED means a rumor, insider report, search lead, or event-specific claim for which the retrieved material did not provide a reliable public confirmation.

The distinction matters because a global exhibition, a student challenge, a corporate hackathon, and a college fest can look similar while having different authorship. A page can prove that a brand held a program without proving that the brand wrote a problem for Craft N Code. Likewise, a winning project can reveal what judges rewarded without proving that the original prompt demanded that feature.

1.3 How to use probabilities

The percentages below are operational estimates. They are not frequencies computed from a complete census of hackathons, because the retrieved evidence is incomplete and sponsor-specific Indian college records were sparse. A percentage such as 35% means "if a Google-like question is released under the stated uncertainty, this is the working branch probability," not "Google has used this theme in 35% of events."

The model gives extra weight to three features: an observed public winner or prompt, a sponsor's current developer-facing product direction, and fit with a 24-hour student build. It discounts a pattern when the source is a participant recap, a secondary article, a title-only listing, or a result that does not establish India or sponsor authorship.

5.2 Why the Accenture shape differs

The Accenture inference is about framing. A consulting-oriented prompt usually becomes stronger when it names an organization or service owner, a workflow bottleneck, a user or beneficiary, constraints such as privacy or legacy data, and a measurable outcome. That is different from a Google-style open-ended social tool, an Apple playground, a Meta model capability demo, or an Adobe creative workflow.

The human-in-the-loop prediction is also an inference, not a retrieved rubric. In a patient-care, manufacturing, or business-insights case, the safe demo is not "AI decides." It is "AI gathers and prioritizes evidence, then an authorized person reviews and acts." This maps exactly to Team 511's complaint tracker, deadline queue, and evidence-ranked intake system.

11. Per-Sponsor Build Orders for Team 511

11.1 If Google sets the question: build BriefLens

Expected problem text - INFERRED: "Students or citizens cannot find the important information in a large, changing collection of documents and messages. Build a grounded assistant that ingests the collection, ranks the most relevant evidence, summarizes it for a defined user, extracts deadlines and next steps, and cites the source for every important claim."

Winning skill profile: retrieval and ranking, document parsing, prompt and evaluation design, simple but trustworthy UX, and an evidence-based pitch. The strongest demo is not a chatbot answering arbitrary questions. It is a fixed corpus, a difficult query, a ranked evidence view, a concise answer, a deadline, and a correction path.

What to build: use the existing engine as BriefLens. Add a source map, confidence bands, duplicate and contradiction flags, multilingual or plain-language output, and an action queue. Keep Kavach as an optional security layer that flags suspicious links or calls in the same evidence workflow. If the actual prompt is education, the input becomes lectures and course notices; if accessibility, the output becomes voice, large type, and language-aware action cards.

Crowded-lane risk: generic RAG and generic summarization. The defense is measurable reliability: source-grounded answers, ranked alternatives, deadline extraction, and a visible metric. A judge should be able to remove one source and see the answer change, which demonstrates that retrieval is real rather than decorative.

11.2 If Apple sets the question: build Kavach Swift

Expected problem text - INFERRED: "Create a compact, accessible Swift experience that helps a person understand and act on a difficult everyday situation. Demonstrate the idea through an interactive playground or native application, with privacy-conscious data handling and a clear user benefit."

Winning skill profile: SwiftUI, interaction design, accessibility, local or lightweight inference, native polish, and a short live demo. Avoid spending the time on a large server. Use a small synthetic data set and make the state transitions obvious.

What to build: create a native call-safety timeline. The user selects or records a synthetic call event, sees the extracted signals, inspects why the risk score changed, chooses report, dismiss, or ask-for-help, and sees the next safe action. Make the app usable with large text, VoiceOver-compatible labels, keyboard or switch-style navigation where feasible, and a privacy explanation. If the prompt is about learning or accessibility rather than calls, retain the timeline and change the content model.

Crowded-lane risk: a generic iOS wrapper, health advice with unsupported claims, or an attractive demo with no user outcome. The defense is one interaction that is both useful and explainable. The app should work with no account, synthetic data, and a clear boundary around what it does not decide.

11.3 If Meta sets the question: build Kavach Circle

Expected problem text - INFERRED: "Help a community or operator define a trust or safety rule in ordinary language and apply it to text, audio, images, or video. Detect relevant events, show the evidence and uncertainty, route the case to a human, and learn from corrections without requiring a custom model-training pipeline."

Winning skill profile: multimodal preprocessing, open-model or API integration, agent tool use, safety evaluation, media UX, and a human escalation story. The LlamaCon CCTV example indicates why a natural-language rule plus operational control is stronger than a model benchmark [6].

What to build: take the Kavach call-security product and make the user define a rule such as "flag a call that pressures the user to reveal a one-time password." Process a synthetic transcript and screenshot, show the matched evidence, expose uncertainty, and send the case to a moderator or trusted contact. Add a false-positive feedback path and a privacy-preserving redaction step. If the prompt asks for fraud, community moderation, or content safety, the same architecture works.

Crowded-lane risk: a surveillance demo with no consent, an accusation engine with no appeal, or a chatbot that never takes an operational action. Use synthetic media, reversible recommendations, human approval, and explicit evaluation for false positives and false negatives.

11.4 If Accenture sets the question: build Kavach Ops

Expected problem text - INFERRED: "A service organization has fragmented reports, calls, and documents and cannot route urgent cases consistently. Build an AI-assisted workflow that extracts the relevant facts, ranks urgency, recommends an owner and next action, explains the evidence, and records human approval and outcome metrics."

Winning skill profile: domain framing, workflow and data modeling, integration, role-based UX, auditability, and presentation. The concrete Accenture labels show that accessibility and bounded personal services can sit beside AI detection concepts [8], so the team should not assume the prompt must be a finance dashboard.

What to build: use the complaint tracker as the front door. Ingest a call transcript, complaint form, PDF, and photo. Extract entities and deadlines, assign risk, generate a case card, route it to a role, and record the resolution. For patient care, use a synthetic patient complaint and a nurse or supervisor approval. For manufacturing, use an incident report and maintenance owner. For speech accessibility, make the output an accessible communication workflow rather than claiming full sign-language translation.

Crowded-lane risk: a consulting-style deck with no working workflow or a dashboard that produces a score without a decision. The defense is a single case journey, one human approval, one audit trail, and one measured outcome such as triage time or unresolved backlog.

11.5 If Adobe sets the question: build SignalStory

Expected problem text - INFERRED: "Turn fragmented source material and a defined brief into consistent, editable, channel-ready creative assets. The workflow must preserve the source of important claims, respect brand or safety constraints, provide variants, and keep a human creator in control of final approval."

Winning skill profile: visual design, front-end interaction, asset orchestration, prompt and template engineering, provenance, and a compelling before/after demo. The Sparky description suggests that a visual node workflow can be more distinctive than a plain generation endpoint.

What to build: let a user select a verified complaint or safety event, extract the key message, rank the audience-relevant facts, choose a template, and generate a public-service card or internal alert. Show the source excerpt behind the card, redact private data, let a human edit the copy and image, and export multiple sizes. If the statement explicitly requires a creative campaign, change the labels and templates but keep the source-to-asset pipeline.

Crowded-lane risk: a generic text-to-image interface, fabricated claims in a generated poster, or a polished design with no measurable workflow benefit. The defense is editable provenance, constraints, and time saved from brief to approved asset.

Reject an API demo that would work just as well with any sponsor. Reject a dashboard that cannot show a decision. In a 24-hour context, a smaller reliable workflow beats a broad platform with a fragile integration.

13. Counterevidence, Failure Cases, and Update Rules

13.1 Brand association is not authorship

A sponsor logo can mean cash support, credits, mentors, a judging prize, a developer tool, or a problem author. The retrieved Craft N Code evidence does not distinguish those roles. The team should therefore search the released statement for direct product constraints, not infer authorship from sponsor order or logo size.

13.2 Winners lists are a biased sample

Meta's CCTV winner is a strong official case, but one winner cannot establish the distribution of all LlamaCon projects [6]. The participant recap adds directional evidence about video, agents, and mixture-of-experts, but it is not a judging report [7]. Google's official page confirms a winner and top 10 without exposing project detail [4]. These examples are best used to identify mechanisms judges can see, not to predict a historical percentage.

13.3 Student format may dominate corporate DNA

Apple's playground format is visible in the official challenge description [5]. Adobe's creative workflow may require a visible artifact. Accenture's problem labels may still be simplified for a college contest [8]. A sponsor-set question can preserve company DNA while reducing the domain to one user and one demo. Team 511 should not overbuild enterprise infrastructure or multimodal training when the judge only needs a credible prototype.

13.4 Safety and privacy are not optional add-ons

Kavach is a useful differentiator, but call content, identity, health, and community reports are sensitive. The retrieved sources do not provide a Craft N Code privacy rubric, so the team should choose the conservative design: synthetic inputs, redaction, explicit consent, human override, reversible actions, and a clear statement of limitations. This is an INFERRED design recommendation, not a claimed organizer requirement.

13.5 Product names can be stale or unconfirmed

The Google source gives an agentic Gemini-era signal [1], and Adobe gives a Firefly creative co-pilot signal [9]. The retrieved material does not verify "Gemini 3" as the exact current requirement. If the released prompt names Gemini, Llama, Firefly, Swift, or an Accenture platform, use that named constraint; otherwise keep the adapters replaceable.

13.6 Update rule when new evidence appears

Upgrade a branch to VERIFIED only when one of the following appears: an organizer post naming the sponsor as problem author; a problem PDF or portal showing the sponsor's exact prompt; a participant screenshot that can be corroborated by the event page; or the live statement itself. Downgrade any branch if the prompt's acceptance criteria conflict with its expected family. Do not let a rumor outrank the text shown to every team.

14. Synthesis: One Engine, Five Judgeable Skins

The five sponsor archetypes differ on mechanism, scope, trade-off, and time horizon. Google favors a broad beneficiary and a grounded information or agent workflow; its trade-off is theme ambiguity and a crowded RAG field. Apple favors compact, native, interactive experiences; its trade-off is that a backend-heavy solution may be invisible or off-format. Meta rewards model capability made operational, especially multimodal control; its trade-off is safety, false positives, and data sensitivity. Accenture favors an organizational workflow with a human owner and metric; its trade-off is presentation risk and the temptation to build a dashboard instead of a product. Adobe favors a visible creative pipeline and editable output; its trade-off is generation crowding, provenance, and the need for visual polish.

The non-obvious tension is that the team's strongest technical asset, the ingest/summarize/rank engine, appears most Google-like, while its strongest product story, Kavach, appears most Meta-like or Accenture-like. That is not a conflict. In every branch, the engine can be the evidence layer and Kavach can be the trust, privacy, or escalation layer. The skin changes the user and output, while the internal objects stay stable.

The second tension is between sponsor novelty and judgeability. A new model name may be fashionable, but a judge can score a clear workflow more reliably than a vague claim about model power. Meta's observed winner makes the model capability visible through a control-room operator [6]; Adobe's observed Sparky makes the workflow visible through nodes and image manipulation. Team 511 should pursue the same principle: make the transformation, evidence, and human decision visible in the first minute.

The final integrated recommendation is a two-stage build. First, make a sponsor-neutral decision cockpit that can ingest a small corpus, rank evidence, summarize, extract deadlines, and create a case. Second, attach one sponsor-specific output: native interaction for Apple, multimodal escalation for Meta, human-owned case workflow for Accenture, visual creative asset for Adobe, or grounded answer for Google. This preserves optionality without producing five half-built products.

15. Final Recommendation to Team 511

Before the release, prepare five one-screen mockups and one shared data schema, not five separate codebases. Name the generic engine Signal Core, keep Kavach as the safety and escalation module, and write a five-line adapter for each branch. At 21:30, select the branch whose nouns and acceptance criteria match the statement, then delete every feature that does not support that branch's one acceptance test.

If the team receives no sponsor-specific clue, choose the Google/Accenture hybrid: a source-grounded intake and prioritization system with a human approval queue. It is the most reusable fallback because it can ingest documents, complaints, calls, reports, or notices and can output a summary, case card, deadline, creative brief, or safety escalation. Do not claim that this is the official Craft N Code problem; it is the best response to uncertainty.

If the question is set by Google, Team 511 should build BriefLens: a grounded, citation-first information and deadline assistant. If it is set by Apple, build Kavach Swift: a polished, accessible native safety interaction. If it is set by Meta, build Kavach Circle: a multimodal, user-defined trust-and-safety agent with evidence and human override. If it is set by Accenture, build Kavach Ops: an enterprise case-triage workflow with owners, approvals, and metrics. If it is set by Adobe, build SignalStory: a source-grounded, human-editable creative workflow. If the question is set by an unknown sponsor or club track, build the sponsor-neutral decision cockpit and skin it only after the acceptance criteria are clear.
