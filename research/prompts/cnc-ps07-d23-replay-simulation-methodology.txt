# CNC PS-07 WAVE 4 (REPLAY) — REPLAY SIMULATION METHODOLOGY: BUILDING + VALIDATING EVENT REPLAYS

OFFICIAL PROBLEM STATEMENT (verbatim, Craft N Code 2026):
Title: Cyclone & Flood-Resilient Smart Agriculture Advisory System
Body: Design an AI/IoT-based early-warning and advisory platform that integrates IMD alerts with hyperlocal farm data to recommend pre-disaster actions and post-disaster recovery steps for farmers in Odisha. It must work via SMS/IVR for low-literacy users.
Objectives:
1. Minimize crop loss during extreme weather events.
2. Ensure accessibility for low-literacy and non-smartphone users.
3. Provide actionable, time-sensitive agricultural advice.
Features:
1. Integration with IMD alerts and local farm data profiles.
2. Automated advisory generation for pre and post-disaster.
3. SMS and IVR (Voice) delivery system.

## Core line
Statement-faithful research for building REAL-EVENT REPLAY simulations: reconstruct
past Odisha cyclones/floods from real data, run our advisory engine against them,
and validate the simulated outcomes against what actually happened.

Research the methodology for building a realistic event replay simulation that our advisory engine can be tested against:
- Scenario construction from real event parameters: how to reconstruct a cyclone event (wind field, pressure, rainfall, surge) from best-track + station data for simulation (Holland wind field with real parameters, spatially interpolating station observations).
- Monte Carlo with REAL uncertainty: sampling from observed station data distributions, spatial correlation of hazard fields (Jayaram-Baker style for wind/rain), how many scenarios for stable results.
- Flood reconstruction: rainfall-runoff from real rainfall data, DEM-based inundation on real terrain, validation against observed flood extents (SAR maps).
- Crop damage modeling: applying stage-specific fragility curves to the reconstructed hazard at plot level, comparing simulated damage vs reported district damage.
- VALIDATION PROTOCOL (the Ariadne discipline): acceptance criteria for the replay: simulated damage within X% of reported damage, simulated inundation matches SAR extents at Y% IoU, warning lead time reproduction. Published examples of hindcast validation for cyclone/flood models.
- Agent-based farmer behavior: modeling farmer responses to advisories (do they harvest early?), what-if runs (advisory issued at T+0 vs T+12: how much loss avoided), published anticipatory action evaluations (WFP/FAO anticipatory cash studies).
- The counterfactual engine: given real farmer behavior vs advised behavior, estimate loss differential. Published methodologies for evaluating early warning effectiveness.
- What tools exist: open-source flood/cyclone modeling (HEC-RAS, LISFLOOD, Delft-FEWS open components, python libs), what a student team can actually run.

## Required output structure (follow EXACTLY)
1. EXECUTIVE SUMMARY: 6-10 bullets, each with [n] source tag.
2. EVENT DATASET: per event: what exists | named source (URL + date) | format | resolution | access | reliability A-D
3. COVERAGE TABLE: source families x useful hits x noise/missing x coverage judgment (A-D)
4. WHAT IS MISSING: exact gaps (which event has no hourly data, which district has no damage figures).
5. HOW IT FEEDS THE REPLAY SIMULATION: which simulation layer (hazard field, crop damage, advisory timing, recovery) and how it validates the engine.
6. REAL-vs-FILLER: usable vs decorative. Evidence only.
7. NOISE LOG: searched and discarded.
8. VERDICT: GO / PARTIAL / GATED with reasons, for building a realistic event replay simulation.
